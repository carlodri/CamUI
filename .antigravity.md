# CamUI for PiCamera2

Lightweight web interface for Raspberry Pi camera modules, built on the modern `picamera2` Python library and Flask.

---

## Project Overview
- **Core Stack:** Python 3, Flask, Pillow (PIL), HTML5, JavaScript (Vanilla), CSS3.
- **Target Platform:** Raspberry Pi OS Bookworm or newer (due to `picamera2` and `libcamera` dependencies).
- **Core Function:** Enables multi-camera video streaming, real-time configuration of camera parameters (exposure, white balance, autofocus, sensor mode, resolution), capturing high-resolution photos, saving/loading camera profiles, and basic photo editing in a web UI.

## Core Workflows & Logic

### 1. Multi-Camera Initialization
The `CameraObject` class in `camera.py` encapsulates a single connected camera. During instantiation:
- Connects to `picamera2` using the camera index (`Num`).
- Generates resolutions, filters incompatible options, and loads the active configuration.
- Checks hardware features (e.g., auto-focus is filtered out if using older camera modules).

### 2. Thread-Safe Live Video Streaming
`StreamingOutput` extends `io.BufferedIOBase` and uses `threading.Condition` locks to buffer and pipe raw camera JPEG frames synchronously to the `/video_feed_<num>` Flask response without race conditions or resource leaks.

### 3. High-Quality Photo Capture
Instead of taking a screenshot of the low-resolution video stream, the system switches the camera mode temporarily to maximize resolution and quality when capturing a still image, saving it directly to `/static/gallery`.

### 4. Custom Profiles
Configurations are serialized and stored as JSON files under `static/camera_profiles/`. They can be saved, loaded, and reset per camera index.

## Development & Deployment

### Run Locally (Host)
Ensure dependencies (`flask`, `picamera2`, `Pillow`) are installed:
```bash
python -m camui --ip 0.0.0.0 --port 8080
```

### Run Diagnostics
Inspect connected cameras and print capabilities:
```bash
python -m camui.diagnostics
```

### Run with Docker
Must be run on an ARM platform with a connected camera:
```bash
# Build
docker build -t camui .

# Run with privileged access to camera devices
docker run --rm -it --privileged \
  -p 8080:8080 \
  -v /run/udev:/run/udev:ro \
  -v camui-gallery:/app/static/gallery \
  camui
```

## Coding Guidelines & Standards

- **Hardware Fail-safes:** Always wrap camera acquisitions, property queries, and control changes in `try-except` blocks. If no cameras are connected, fallback to simulated behaviors or placeholder frames.
- **Thread Safety:** Do not share `picamera2` instances or outputs across threads without acquiring condition locks.
- **UI Responsiveness:** Any adjustment in camera controls (e.g. exposure or ISO) must instantly update the live view. Ensure ajax requests are lightweight.
- **Aesthetic Excellence:** Frontend UI should remain clean and modern, supporting mobile-responsive layouts. Use Vanilla CSS/JS and avoid adding unnecessary runtime frameworks.
